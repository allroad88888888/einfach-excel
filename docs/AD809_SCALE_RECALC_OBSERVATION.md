# AD-809 大规模已填充重算 E2 观察

## 结论

在本记录的 revision 与环境下，**实际达到的重算档位是 7,000,000 个非空单元格**（7,000 行 × 1,000 列），内嵌 7,000 深单链与一个整列 `SUM(A:A)` 聚合，headless 直连 WASM worker 工作簿完成了导入、按需求值、编辑与重算全流程。核心事实：

- 导入 700 万格后公式求值计数为 **0**（懒到读取，AD-821 契约在该规模成立）；
- 12×4 首屏窗口读取只求值 **13** 个公式（窗口内 12 个链节 + 1 个整列 SUM），与工作簿共 7,001 个公式、700 万格无关；
- 全链尾格首读、编辑后重算的求值工作量都是 **O(链长)** 量级，累计求值 20,861 次，约为总格数的 **0.30%**。

**请求的千万档位（10,000×1,000）没有达成**：同一 direct 灌入路径三次尝试都在累计接受 7,340,000 格时被 WASM 引擎 trap 终止（记录见 [AD-808 记录](AD808_SCALE_INTERACTION_OBSERVATION.md)与本记录原始载荷）。完整机器可读载荷见[原始观察记录](observations/ad809/scale-recalc-2026-08-17.json)。

## 实际输入与复现

夹具在测试进程内确定性生成，经 wire 协议非原子 `direct` 导入按 10,000 格 chunk 灌入（非文件路径，不改动任何 worker 保护或配置）：

- 第 0 列（A）：每行数值 `1`；
- 第 1 列（B）：`B1 =A1`，第 r 行 `=B(r-1)+A(r)`——7,000 深依赖单链；
- `C1 =SUM(A:A)`（整列引用）；
- 其余全部为 AD-806 文本 `r{row}c{col}`。合计 7,000,000 非空格、7,001 个公式。

```sh
NO_PROXY=localhost,127.0.0.1 EINFACH_E2E_PORT=5187 AD809_SCALE_ROWS=7000 \
  npx playwright test ad809-scale-recalc --project=wasm --reporter=line
```

测试文件：`excel/solid-excel/e2e/perf-virtual/ad809-scale-recalc.spec.ts`。

## 运行事实

revision `986cd74e564da8e998cef7956ae41b741bab4895` 加本轮未提交文件；macOS 26.5.2（Apple M4、16 GiB）、Node v24.14.0、Playwright 1.59.1、Chrome 147.0.7727.15、`wasm` project。一次干净运行通过（29.7s 含 web-server 准备）。导入统计 `accepted=7000000, formulas=7001, errors=0`，页内导入耗时 22,089 ms。耗时为宿主观测的单次 RPC 墙钟毫秒。

| 阶段                             | 耗时 ms | `formulaEvalCountTotal` 增量 | 结果断言                    |
| -------------------------------- | ------: | ---------------------------: | --------------------------- |
| commit 后基线                    |       — |                    0（累计） | `formulaCount=7001`、零求值 |
| 12×4 窗口读（48 格，含 B1..B12、C1） |    38.6 |                           13 | 窗口外公式未被求值          |
| 链尾 B7000 首读                  |      77 |                       13,847 | 显示 `7000`                 |
| 链尾 B7000 重复读                |     0.1 |                            0 | 完全记忆化                  |
| `setCell` A1=2（写命令）         |    71.8 |                        7,001 | 同步重导出已物化依赖者      |
| 编辑后读 C1                      |     0.1 |                            0 | 显示 `7001`                 |
| 编辑后读 B7000                   |     0.0 |                            0 | 显示 `7001`                 |

最终累计求值 20,861 次 / 7,000,000 格 ≈ 0.30%，远小于总格数——这是 AD-821「按需求值」契约在该规模下的实测印证。

两点计数口径说明（都已在测试内注明）：

1. **深链传递求值的计数是引擎特定口径**：WASM 引擎按"每个传递格求值 + 深链 FAULT 重放"计数（链尾首读 13,847 = 6,988 个未求值链节的首算加重放）；TS worker 引擎对同样的读取按"顶层 derive 次数"计数（同场景报 1）。跨引擎只可比对值的正确性与"是否 O(链长)"，不可直接比计数。
2. **编辑已物化链根时，重算发生在写命令内**：`setCell(A1)` 同步重导出全部已物化的脏依赖者（+7,001），其后的读取全部记忆化（增量 0）。「懒到读取」适用于从未被读过的公式；已读过（已物化）的公式在写入时同步刷新。

## settled 与解释边界

settled 定义：每阶段以其 worker RPC promise resolve 为落定，`debugCounters` 在每阶段前后立即读取，`setCell` 后有独立采样点。

本记录只描述该 revision、构建、夹具与环境的一次运行。耗时是单次采样，不构成基准、吞吐或 SLO 主张；7,340,000 的灌入 trap 是本构建 direct 路径的边界，不是引擎容量结论；求值计数是调试口径，不同引擎不可直接互比；未覆盖跨 sheet、易失函数、并发编辑等场景，不能外推。稳定的有界性质（导入零求值、窗口读求值数 = 窗口内公式数、重复读记忆化、链尾求值 O(链长) 且远小于总格数）已由 AD-812 固化为常驻契约断言。
