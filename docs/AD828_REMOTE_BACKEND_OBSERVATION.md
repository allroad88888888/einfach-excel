# AD-828 跨网络后端的视口浏览观察

## 范围

本记录是以仓库修订 `986cd74e564da8e998cef7956ae41b741bab4895` 为基线、加上本次
AD-828 引入的演示文件，在 2026-08-17 的一次实际浏览器观察。它验证同一套 vNext UI
能通过 `SpreadsheetBackend` 端口对着一个 **HTTP 网络对端** 浏览工作簿，且服务端
计量到的响应载荷跟视口窗口走、不跟工作簿总量走。完整原始记录与探针在：

- [原始观察记录](observations/ad828/remote-backend-viewport-2026-08-17.json)
- `excel/solid-excel/demo-remote/probe.mjs`（探针）、`server.mjs`（服务端）、
  `http-backend.ts`（适配器）、`RemoteViewportDemo.tsx`（演示页）

环境：macOS 26.5.2（25F84）、Node v24.14.0、Playwright 1.59.1、
HeadlessChrome 147.0.7727.15、vite 5.4.21 dev server（`127.0.0.1:5186`）、
演示服务端 `127.0.0.1:5303`（同机回环）。

## 场景与方法

服务端（`demo-remote/server.mjs`，零依赖 node:http）在进程内存中物化一个确定性
种子工作簿：100,000 行 × 6 列 = 600,000 个已填充单元格（每行一个 `R{n}` 标识、
四个派生数值、一个类目文本）。三个 POST 端点与契约
（`excel/spreadsheet-ui-core/src/backend/types.ts`）的三必需方法一一对应；适配器
（`demo-remote/http-backend.ts`）**只**实现这三个方法，其余可选端口全部缺席，
UI core 按方法在位性自行隐藏对应功能面。

字节口径：服务端对每个响应记录 **HTTP 响应体的 UTF-8 字节数**（JSON 文本），按
端点累计进 `/api/stats`，同时以 `x-einfach-response-bytes` 头回带。同口径全簿基线：
把全部 600,000 格按与视口响应完全相同的 DisplayCell JSON 形状序列化成一个 `cells`
数组，实测为 **47,285,608 字节**——这是同一序列化口径下的对照数字，不是任何传输
实现。

探针（`demo-remote/probe.mjs`）用无头 chromium 打开 `/?backend=remote`，分三个
阶段行动，每阶段的 settled 条件是服务端 `/api/stats` 的 totals 连续 4 次 200ms
轮询不变：

1. **首屏**：等到 `data-row=0,data-col=0` 的格子渲染出远端值 `R1`；
2. **三次单屏滚动**：每次 `scrollTop += clientHeight`；
3. **三次触边滚动**：每次把 `scrollTop` 推到滚动表面底端，强制一次重锚。

演示网格视口声明 100,000 行 × 6 列；渲染窗口 = 滚动表面（约 5× 视口，此处约
100 行 × 6 列 = 600 格）。

## 实际观察

| 阶段         | visible-projection 请求 | 响应体字节 | 阶段后渲染行区间（格数） | 样本值               |
| ------------ | ----------------------: | ---------: | ------------------------ | -------------------- |
| 首屏         |                       1 |     44,707 | 0–99（600 格）           | `R1`、`north`、`R100` |
| 三次单屏滚动 |                      +1 |    +45,251 | 43–142（600 格）         | `R44`、`west`        |
| 三次触边滚动 |                      +3 |   +137,214 | 223–322（600 格）        | `R224`、`direct`     |
| **会话合计** |                   **5** | **227,172** |                          |                      |

- 整个会话只出现 `read-visible-projection` 请求；`read-range-projection` 与
  `set-cell-input` 均为 0。每个响应约 44–46 KB，对应一个约 600 格的窗口。
- 三次单屏滚动中只有第三次越过重锚阈值产生了 1 次请求——表面内滚动是零 RPC 的，
  与 worker 后端下的窗口化行为一致。
- 对照：会话响应体合计 227,172 字节；同口径全簿序列化为 47,285,608 字节。载荷
  规模由窗口决定，工作簿总量只影响服务端内存。
- 浏览器控制台与页面错误均为 0。同日第二次完整重跑得到逐阶段完全相同的请求数与
  字节数（44,707 / 45,251 / 137,214）。

## 解释边界

- 这是**演示服务**：无鉴权、无持久化、无压缩、无缓存，也不含任何并发或生产承诺；
  写入路径只验证了「不支持的输入被结构化拒绝」这一契约行为。
- 两端都在同机回环上，不涉及真实网络的延迟、带宽、丢包或代理；本记录不构成任何
  延迟、吞吐或性能结论。
- 字节口径只计 HTTP 响应体，不含请求体、头部、TCP/TLS 或浏览器内部开销；全簿
  基线是同口径序列化的对照数字，不代表任何实现真的会传输它。
- 滚动是程序化的三段固定动作；不同视口尺寸、滚动速度或重锚阈值会得到不同的请求
  切分。结论仅限本修订、本夹具、本浏览器与上述 settled 定义，不外推为其它规模或
  与任何竞品的比较。
