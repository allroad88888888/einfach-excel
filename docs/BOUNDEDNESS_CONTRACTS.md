# Boundedness capability contracts

This document makes the externally useful promises guarded by the
`perf-virtual` suite easy to find. It is a mapping, not a benchmark report:
the numeric ceilings below are regression-test observables for the cited demo
and browser run. They are **not** throughput, latency, memory, or production
SLA guarantees.

The source case register is
[`perf-virtual/CASES.md`](../excel/solid-excel/e2e/perf-virtual/CASES.md).
Rows marked “diagnostic” expose a debug-only test probe; application code
should rely on the capability described in the contract, not on that probe.

## Reading these contracts

- “Oversized” means above the store’s operation-specific limit. It does not
  imply that all rectangle sizes have identical memory or elapsed-time costs.
- A capability marked “requires” can be unavailable on a backend. The cited
  store paths deliberately decline that oversized operation instead of
  silently expanding it on the main thread.
- The contracts cover the cited Playwright flow only. Re-run the linked test
  when changing virtualization, selection, range, import, or worker behavior.
