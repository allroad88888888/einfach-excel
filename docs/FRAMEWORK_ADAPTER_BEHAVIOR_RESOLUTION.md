# 框架适配器行为分歧裁决规程

父节点：[AD-300 框架适配层](adoption-issues/AD-300-framework-adapters.md) 中的
AD-391。

## 目的

本文规定 React、Vue 或其他未来框架适配器在同一用户可见行为出现分歧时，如何
收集证据、确定裁决对象、记录结论与安排验证。它让一次裁决可复核，而不把某个
框架的实现细节误写成共享事实。

本规程只适用于适配层已观察到的行为分歧。它不创建组件、包、后端端口或共享
API；也不替代具体叶子的实现与独立验收。

## 已知边界

[档 1 范围](FRAMEWORK_ADAPTER_TIER1_SCOPE.md) 是未来适配器的目标行为边界，不是
任何框架已经可用、可安装或彼此等价的声明。其“解释边界”要求将已实现行为如实
记为各自现状，不得由一个框架反推另一个框架已有同一能力。

现有可移植性分类也把职责分开：

- [Grid 边界](FRAMEWORK_GRID_PORTABILITY_BOUNDARIES.md) 将纯几何候选与 DOM、生命周期
  和渲染职责分开；
- [编辑边界](FRAMEWORK_EDITING_PORTABILITY_BOUNDARIES.md) 将编辑状态机、键盘意图与
  原生事件/焦点职责分开；
- [选区边界](FRAMEWORK_SELECTION_PORTABILITY_BOUNDARIES.md) 将选区 Atom 事实与 pointer、
  ARIA、渲染表面分开；
- [交互边界](FRAMEWORK_INTERACTION_PORTABILITY_BOUNDARIES.md) 说明其余交互规则与框架
  拥有的事件、元素、挂载资源之间的界线；以及
- [无头挂载契约](HEADLESS_MOUNTING_CONTRACT.md) 与 [DOM 测量契约](DOM_MEASUREMENT_ADAPTER_CONTRACT.md)
  分别规定投影/命令生命周期和测量资源的所有权。

因此，“行为相同”只能指已定义的可观察结果。事件对象、响应式桥接、元素引用、
清理方式、组件结构与样式组织仍可由各框架不同地实现。

## 可裁决的行为与不可比较的实现

提出分歧前，记录者必须把问题写成一个可从外部观察的陈述，例如“在某一编辑
会话中，取消后显示值与选区是否恢复到指定状态”。不能只写“两个 hook 不一样”。

下表用于把问题归到已有边界；它不增加这些边界的能力承诺。

| 分歧类别         | 可比较的对象                           | 首选事实来源                                                                                                       | 不能据此比较的对象              |
| ---------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------- |
| 投影与显示       | 请求、结果、过期结果与显示快照         | [无头挂载契约](HEADLESS_MOUNTING_CONTRACT.md)                                                                      | 框架订阅 API 或渲染调度         |
| 选区与编辑       | 命令前后 Atom 驱动的用户可见结果       | [编辑边界](FRAMEWORK_EDITING_PORTABILITY_BOUNDARIES.md)、[选区边界](FRAMEWORK_SELECTION_PORTABILITY_BOUNDARIES.md) | input ref、焦点实现或事件包装   |
| 键盘与输入       | 已定义意图的进入、取消、提交与默认行为 | [编辑边界](FRAMEWORK_EDITING_PORTABILITY_BOUNDARIES.md)                                                            | 事件监听器注册形状              |
| 滚动、冻结与尺寸 | 几何输出、逻辑位置与可见窗口           | [Grid 边界](FRAMEWORK_GRID_PORTABILITY_BOUNDARIES.md)、[DOM 测量契约](DOM_MEASUREMENT_ADAPTER_CONTRACT.md)         | ref 生命周期或 observer 实现    |
| 挂载与清理       | 会话资源停止后的可观察后果             | [无头挂载契约](HEADLESS_MOUNTING_CONTRACT.md)                                                                      | 各框架的 effect 或 cleanup 语法 |

若问题落在档 1 明确排除项，或现有契约未定义该行为，则它不是“修正为一致”的
依据。记录者必须把它标为未决范围，而不是虚构默认规则。

## 证据优先级

同一行为有冲突证据时，按下列优先级裁决。高位证据只在其明确的对象、条件和
排除项内优先；不能外推到未写出的场景。

1. 已有的明确状态/生命周期契约与其所指向的源码事实，例如投影结算、命令派发
   或挂载资源所有权；
2. 已验收叶子中针对该框架、该场景的测试和实现证据；
3. 范围冻结文档对“应覆盖哪些表面”的规定；
4. 可复现的人工观察、issue 描述或单一框架的未验收实现；
5. 推测、组件命名、相似的框架 API，或“通常应当如此”的类比。

第 1 项定义现有语义时，适配器必须遵从它，除非另有获批的、更精确的契约改变。
第 2 项只证明该框架和该场景的当前事实；它不是另一个框架的默认行为。第 3 项
规定目标覆盖面，却不填补没有现有契约的键位、时序、错误显示或浏览器策略细节。

当同一优先级的证据互相矛盾，或最高证据无法判断时，结论必须是“未裁决”，并
创建一个范围清晰的后续叶子。不得为了关闭分歧而选择更容易修改的一端。

## 裁决流程

1. **冻结问题。** 写出用户动作、起始状态、可观察结果、受影响框架和复现步骤；
   将一个问题限制为一个行为断言。
2. **标记边界。** 指出它是投影、编辑、选区、键盘、几何、测量或挂载清理问题，
   并链接上节表中的适用契约或边界文档。
3. **收集逐框架事实。** 对每个参与框架分别列出实现位置、测试命令与输出；未有
   证据的框架写“未验证”，不得补成“不同”或“相同”。
4. **应用优先级。** 保留每条证据的条件、时间和范围，说明哪一条控制结论；若
   它只覆盖一端，则明确其不对另一端作推断。
5. **选定处置。** 处置只能是保持已有行为、使实现符合既有契约、补充一个更精确
   的契约，或登记为未决范围。后两种处置必须拆为可独立验收的叶子。
6. **定义验收。** 为受影响的每个已实现适配器写出定向测试场景与命令；若某框架
   未实现，不为它编造测试通过结果。
7. **记录与复查。** 将下列记录模板填入该行为的叶子或专用决策记录，并链接到
   实现提交及独立验收。只有验收完成的那一端才能标为已验证。

裁决的输出是一个对当前证据负责的结论，不是发布说明、兼容性保证、性能保证、
安全保证、支持承诺或服务等级协议。

## 行为裁决记录模板

每个记录只回答一个行为断言。字段没有证据时保留“未验证”或“未裁决”，不以
空白暗示通过。

```md
### 行为：<用户可观察的一句话断言>

- 状态：<已裁决 | 未裁决 | 已替换>
- 范围：<表面、起始状态、用户动作、排除条件>
- 参与框架：<逐一列出；未实现或未验证须明确写出>
- 适用边界：<链接到范围/契约/可移植性文档>

#### 证据账本

| 优先级 | 框架或共享层 | 证据链接                 | 覆盖条件   | 事实或结论         |
| ------ | ------------ | ------------------------ | ---------- | ------------------ |
| 1–5    | <对象>       | <源码、契约、测试或记录> | <前置条件> | <不超出证据的陈述> |

#### 裁决

- 控制证据：<最高且适用的证据，或“无”>
- 结论：<保持/对齐到既有契约/补契约/未决>
- 不作推断：<不从哪些实现或范围文字外推>
- 后续叶子：<编号或“无”；每项一个可独立验收的交付物>

#### 验收

- 场景：<动作与预期可观察结果>
- 适用框架：<仅列出已实现且应验证的框架>
- 命令与结果：<可复跑命令、提交、独立验收记录；未运行则明确标注>
```

“已替换”仅表示一份较早的裁决被带有链接的较新记录取代；它不抹去历史实现
或自动改变任何适配器的状态。

## 明确不作的决定

本文不作下列决定：

- 不宣布 React、Vue 或其他框架适配器已可用、可安装、可发布、受支持或行为对等；
- 不把档 1 范围当作精确的键盘、pointer、IME、焦点、错误呈现或跨浏览器规则；
- 不把某框架的 hook、组件树、响应式模型、DOM ref 或资源清理方式指定为共享实现；
- 不重新分配 UI-core、后端、DOM 测量或适配器的所有权；这些仍以已有边界契约为准；
- 不设定版本、发布、兼容性、安全、性能、维护时限或 SLA；以及
- 不替代 [Issue 树的完成口径](ADOPTION_ISSUE_TREE.md#状态口径) 所要求的独立验收。

这份规程与档 1范围一样，只使后续事实和取舍可审计；任何能力仍须由对应实现和
验收证据单独证明。
