# 电子表格交互重整：Issue 树

> 本文件是本地的 Issue 树，不是功能清单或现状报告。
>
> 它只定义后续要推进的交互工作单元：不标完成状态，不判断是否存在 Bug，不排优先级，也不记录验证结论。每个叶子节点开始推进时，才另补交互稿、负责人、技术方案和实施记录。

> 已完成现状审计后的模型分工、依赖波次与修复/重构判定，另见
> [交互执行树](INTERACTION_EXECUTION_TREE.md)。两份文件刻意分离：本文件保持体验范围，执行树才记录技术现状与实施安排。

## 使用约束

- 一个叶子节点必须能以一条用户操作链路说清楚，不能只是“优化某模块”。
- 父节点只负责聚合和排序，不能作为实现任务接收代码改动。
- `入口 → 操作 → 界面衔接` 描述目标体验，不构成完成判定。
- `涉及界面` 用现有 vnext 表面定位范围；不把引擎和后端的内部实现混入交互 Issue。
- `前置` 只写交互依赖，不表示排期或完成顺序。
