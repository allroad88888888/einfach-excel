# AD-618 中文渠道清单

> **性质**：本文是发布「弹药」，实际发布由维护者决定与执行。
> **规则时效**：各站规范按撰写时（2026-08）通行认知整理，**以站方当前规则为准**——发布前复核各站的社区规范/创作规则页。
> **口径**：中文稿不是英文稿的互译，按渠道习惯改写（仓内 AD-616 的既定口径）。

---

## 1. 掘金（juejin.cn）

- **适投内容**：五篇文章的中文版主阵地，前端受众密度最高。文章一（solid-js 双实例）、文章四（backend port）、文章五（React/Vue 适配）最对口；文章三（Rust/WASM parity）挂 Rust/WebAssembly 标签也有稳定读者。
- **规范与禁忌**：
  - 标注原创；选对分类（前端）与标签（`Solid.js` `WebAssembly` `Rust` `开源`），标签影响分发。
  - 标题党、封面党会被推荐算法与举报双杀；但纯平铺标题也吃亏——用「踩坑/裁决/为什么」句式的真实技术叙事最合掘金口味。
  - 文内放 GitHub/npm 链接没有障碍；文末统一放「项目地址 + demo」即可，不要每段插推广。
  - 项目发布类短消息可另发「沸点」，与长文错开。
- **时段通行认知**：工作日早高峰 8:30–10:00 与晚间 20:00 后进推荐流效果较好；周五下午与周末流量偏弱。

## 2. 知乎

- **适投内容**：裁决与争议型选题——文章二（filter/sort 为何判给引擎）、文章三（双引擎 parity 怎么钉）适合专栏长文；也可回答既有问题（如前端表格方案对比、「如何评价 Univer」类问题）。
- **规范与禁忌**：
  - **利益相关必须披露**：回答涉及自己项目时开头写明「利益相关：作者」。知乎社区对隐性软文的反噬最强，披露反而加分。
  - 外链会被折叠/加跳转提示，正文要能脱离链接自立；不要在多个问题下贴同一篇回答（会被判营销号）。
  - 蹭竞品问题要克制：只在真正能回答问题时出现，对比只说带来源的事实（见 checklist FAQ 口径），不贬低对方。
  - 专栏文章与回答可以互链，但同一天不要多点开花。
- **时段通行认知**：晚间 20:00–23:00 是知乎活跃峰值；技术内容长尾靠搜索，时段权重低于内容本身。

## 3. V2EX（分享创造 /go/create，或「创意」区）

- **适投内容**：项目本体一帖（中文语境的「Show HN」）。格式：一句话定位 + demo 链接 + npm 安装命令 + 为什么做 + 求反馈。文章不适合全文贴，可摘要 + 链接。
- **规范与禁忌**：
  - 「分享创造」节点就是发自己作品的地方，自我推广在此合法；但**一个项目一帖**，重大版本更新才值得再发（append 到原帖更受欢迎）。
  - 禁忌：马甲顶帖、标题夸大（「吊打 XX」必翻车）、只发链接不回帖。V2EX 用户提问直接甚至刻薄，作者守帖回应的姿态决定风评。
  - 新注册账号有发帖限制（注册时长/余额门槛以站方当前规则为准）；用有历史的账号发。
- **时段通行认知**：工作日「摸鱼时段」10:00–11:30、14:30–17:00 活跃度高；深夜发帖会沉。

## 4. 少数派（sspai）——裁决：暂缓，不作为本轮渠道

- **理由**：少数派受众是效率工具的**使用者**，不是嵌入式表格组件的**集成者**；「可替换后端的 spreadsheet UI core」在那里没有转化路径。五篇选题没有一篇是消费级角度。
- **保留条件**：若未来写出「一个人用 Rust 重写 Excel 引擎」这类面向大众的开发故事，可投少数派/Matrix 社区；本轮不安排。

## 横向纪律（适用所有中文渠道）

1. 中文渠道与英文渠道受众基本不重叠，可与英文安排并行，但**同语言渠道**同一内容错开日期（见 [schedule.md](./SCHEDULE.md)）。
2. 竞品对比一律用 `docs/UNIVER_PRODUCT_EVIDENCE.md` 的带来源事实口径；中文社区尤其反感拉踩。
3. 规模/性能表述守 README 边界：讲代码契约，不做性能/容量/SLA 主张。
