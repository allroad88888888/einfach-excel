# ADR 0009：公共性能测量方法

- 状态：accepted
- 日期：2026-08-13
- 相关：[AD-500：可验证的性能证据](../adoption-issues/AD-500-performance.md)
- 前置：[ADR 0008：公共性能证据范围](0008-public-performance-evidence-scope.md)

## 背景

ADR 0008 只规定哪些类别可以建设为公共性能证据。要使同一类别的结果可以被
复跑和比较，还需要一份不依赖具体基准实现的采样与统计协议。

本决策规定协议，不产生测量结果。它也不选择具体数据档位、机器、浏览器、
包产物或发布位置；这些信息分别属于后续叶子。

## 决策

公共性能证据的每次测量都采用以下协议。

### 共同采样规则

1. 一个运行只测量一个已命名的场景、一个实现版本和一个数据档位。场景配置在
   该运行内不得变化。
2. 每个场景先执行 **5** 次预热；预热样本只用于初始化运行时、缓存和渲染管线，
   不进入统计。
3. 预热后取得 **20** 个有效样本。样本因脚本错误、未达到场景完成条件或计时
   API 不可用而失败时，记录失败原因并重跑该样本；不能以成功样本替换失败的
   运行而隐去失败。
4. 对有效样本同时报告中位数和 p95。报告必须同时保留原始样本，避免只给出一
   个经汇总的数字。
5. 同一份结果只能比较使用相同场景定义、完成条件和统计规则的运行。改变其中
   任一项时，结果是新序列，不能与旧序列合并。

“场景”“实现版本”和“数据档位”的标识必须随结果关联，但标识的字段、机器与
浏览器信息的记录格式由 AD-504 决定。

### 大表滚动流畅度

一个样本是从预定滚动起点开始，到预定滚动终点稳定呈现之间的一次连续、脚本
驱动的滚动过程。测量收集该过程中的逐帧间隔，并以该样本内落在目标帧预算内的
帧比例作为样本值。

场景定义必须固定滚动方向、距离、容器尺寸、初始位置和终点完成条件。不得把
手动滚动、不同滚动路径或尚未稳定呈现的帧混在同一序列中。

### 公式链重算延迟

一个样本从对指定输入单元写入一个有效新值开始，到指定依赖链末端的目标单元
呈现本次写入对应的结果结束。计时必须覆盖该场景要求的计算和 UI 可观察更新，
但不包含操作者手动输入、网络请求或下一轮的等待时间。

场景定义必须固定依赖链形状、变更输入、目标单元和完成判定。若运行时可异步
调度，完成判定必须等待目标值与本次写入匹配，不能只等待写入调用返回。

### 首屏到可交互

一个样本从一次新的入口加载开始，到用户可在预定单元完成一次编辑且该编辑被
界面确认结束。该边界包括入口加载所需的资源获取、初始化和适用时的 WASM
实例化；不包括加载开始前的浏览器启动时间。

场景定义必须指定入口、预定可编辑单元和确认方式。复用已打开页面、已创建的
工作簿或已完成的 WASM 实例不能作为新的样本。

### 包体积

一个样本是一个已命名可交付产物的字节数。每种产物分别保留 raw 字节数和使用
确定性压缩命令得到的 gzip 字节数；不得将多个产物相加后称作单一产物，也不得
用开发产物替代对外候选产物。

AD-511 负责列出要测量的产物和对外表述的具体命令。本决策仅要求同一产物在
比较时使用相同的构建输入和压缩方法。

## 验证边界

这个协议需要由 AD-505 至 AD-510 的基准页面、场景、数据和导出能力实现；它们
就绪前，不得把本 ADR 当作已经取得公共性能证据。AD-515 负责发布复跑脚本、
原始样本和结果页面。

AD-503 决定哪些结果不构成承诺及其适用边界；本 ADR 不设 SLO、SLA、回归门槛、
性能目标或竞争性结论。AD-504 决定环境记录规范；本 ADR 不定义机器、浏览器、
版本或数据规模的记录字段。

## 后果

后续基准实现必须能够导出 5 次预热以外的 20 个原始有效样本，以及每个失败样本
的原因。不能满足该条件的测量只能作为内部诊断，不能按 ADR 0008 的范围对外
表述为可复跑证据。
