# React Excel 主线执行记录

目标：按每批三个相关功能持续交付完整 React Excel，生产链路仅使用 UI Core atom + Rust/WASM。

## 范围与完成口径

- 原 React 三项启动任务已完成，不能据此宣布完整产品完成。
- 完整功能范围暂以[历史在线 Excel 清单](../solid-excel/docs/archive/online-excel-parity/README.md)
  的 41 项为核对索引；只引用功能范围，不继承 Solid 的实现状态或架构。
- 用户如指定另一份计划，以指定计划为准。Solid、Vue、介绍站当前不作为本目标的交付对象。
- 每项必须有 React 入口、真实 Rust 行为、可复现测试，才能记为完成；部分入口或只有核心单测
  一律记为部分完成。外部数据、身份、持久化服务不能用本地假数据替代验收。
- 下面按原编号合并展示相关项，不删减原清单；原计划明确延后的外部连接保留为延后状态。

Copy As 批次沿用 `runSystemClipboardAtom` 与同一份剪贴板反馈，仅新增只读 `clipboard.export`。
Worker 从 Rust 读取整个选区，复用现有纯文本/Markdown/HTML 编码器后只返回字符串；
不把全选区投影发布到屏幕，不改工作簿 revision 或普通复制/剪切 token，不缓存另一份工作簿。
HTML 使用既有 CSS 白名单及内容转义；Markdown 补充 HTML、链接和强调符号转义后再套原格粗体/斜体。
React 只把 Promise 数据交给 `ClipboardItem`，保持用户手势中的写入，权限失败显示反馈且可重试。
浏览器写入方式参考 [MDN ClipboardItem 构造器](https://developer.mozilla.org/en-US/docs/Web/API/ClipboardItem/ClipboardItem)。
HTML 额外带纯文本版本，Markdown 用 `text/plain` 存源码，不依赖浏览器支持 `text/markdown` MIME。
