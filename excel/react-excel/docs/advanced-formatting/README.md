# 高级文字条件格式

从工具栏打开“条件格式”，选择“文字”或“重复/唯一值”。新增字段仍使用原来的规则目录、保护检查、优先级、Stop、复制、启停、历史与文件链路。

## 通配符

文字条件增加“匹配通配符”和“不匹配通配符”，对整个文字值匹配：

| 模式 | 含义 | 示例 |
| --- | --- | --- |
| `*` | 零个或多个字符 | `ready*`匹配`READY now` |
| `?` | 一个原Unicode标量 | `中文?`匹配`中文🙂` |
| `~*` / `~?` / `~~` | 字面量星号、问号、波浪号 | `a~*`只匹配`a*` |

匹配忽略大小写并保留空白。大小写使用Rust Unicode小写转换，不使用地区规则、完整case folding或Unicode归一化，因此`ß`与`SS`不同；`?`不是字素簇，一个组合字符或多码点emoji可能需要多个`?`。`~`在非特殊字符之前保持字面量，奇数个尾部`~`视为未完成转义。

文字须为1–1024个Unicode标量。空值、超长模式、未完成转义会保留草稿并给出可纠正错误；匹配沿用原生查找器的16,000,000成本预算，超预算时正向与反向规则均跳过该值。原来的包含、不包含、开头、结尾仍按字面量处理`*`、`?`与`~`。

## 基础显示文本判重

“比较依据”默认是“原始值和类型”，兼容已有规则。选“基础显示文本”会比较原生数字格式应用后的文字：数字`1`与文字`1`相同，`0.5`的`0%`格式与文字`50%`相同；`1.04`与`1.03`在一位小数下都显示`1.0`。同一个数字在普通格式和百分比格式下可以不同。

数字文字由现有Rust`CellFormat::format_number`生成；文字和布尔值使用现有`value_to_display`。比较忽略文字大小写、保留空白。真空格、空文字、错误与非有限数字跳过；数字格式生成空文字时也跳过。当前条件格式、地区、字体、列宽和颜色不会进入比较键，避免条件格式自依赖。

每个相关且启用的显示文本规则，在每次显示快照准备统计时，对规则范围稀疏成员同步一次数字显示键到原生format-input atom。范围派生atom读取该输入与既有值facade，缓存重复键。数字格式、值、公式或异步结果变化都在消费缓存之前同步；相同输入复用统计。首次或输入变化时需要两次稀疏成员扫描，未变化时仍有一次同步扫描；不扫描空网格或全部样式，不保留第二份样式。规则删除、替换会释放派生atom与format-input primitive。

## Wire与验证

- `text.condition`：新增`matches-wildcard`、`not-matches-wildcard`。
- `duplicate-values.compareBy`：可选`value`或`display-text`，省略等同旧`value`且不改写旧文件。
- `AFMT-001`到`AFMT-005`分别绑定真实工具栏的通配符匹配、反向匹配、显示重复、显示唯一、数字格式立即更新。原任务`CFADV2`命名经root裁决统一为现有registry合法前缀`AFMT`。
