# 日期批次

本批只做日期输入、日期显示、日期序列填充。三项已接通真实 Rust/WASM，全量验收通过。

## 已实施：统一原生日期基准

公式旧实现以 1970-01-01 为 0，填充使用 Excel 1900 系统，两者曾相差 25569 天。
现在由 Rust `date_serial.rs` 提供唯一序号转换，原有填充与公式都调用它：

- 1900-01-01 = 1，1900-02-28 = 59，兼容日期 1900-02-29 = 60，1900-03-01 = 61。
- 1970-01-01 = 25569，2024-01-01 = 45292；小数部分仍代表一天内的时间。
- 转换不依赖浏览器／操作系统时区；删除逐年循环，极端数值不进入年数遍历。
- DATE 的月份／天数允许溢出，0–1899 的年份按函数语义加 1900；结果必须在可表示范围。
- YEAR／MONTH／DAY、WEEKDAY／WEEKNUM、月末／月偏移使用同一起点；补上相关越界及错误传播检查。
- DATEVALUE 共用无歧义的四位年在前解析，支持 `yyyy-mm-dd`、`yyyy/m/d`，非法日历日期拒绝。

规则参考 [Microsoft 日期系统](https://support.microsoft.com/en-us/excel/date-systems-in-excel)、
[1900 兼容闰日](https://learn.microsoft.com/en-us/troubleshoot/microsoft-365-apps/excel/wrongly-assumes-1900-is-leap-year)、
[DATE 参数规则](https://support.microsoft.com/en-us/Excel/functions/date-function)。
当前不提供 1904 系统切换，也不会擅自给已保存的普通数字加偏移；已有公式按新基准重算。

## 三项功能与手工验收

1. 格内或公式栏输入 `2024-02-29`、`2024/2/29`，原生写入数字 45351，
   同一次编辑设置 `yyyy-mm-dd` 格式，保留其它样式；撤销同时恢复值与格式。
   `'2024-02-29` 是强制文本，`2023-02-29`、`02/03/2024` 等非法／歧义输入仍保留文字。
   日期重新编辑显示原始序号，公式显示原始表达式；不会把显示结果反写成文字。
2. 工具栏 `Date format` 设置 ISO 日期显示，`General format` 恢复数字，原值不变。
   Summary 的 `A20` 是粗体 2024-02-28，`C20:C21` 是斜体月末日期，
   `E20` 是带下划线的兼容日期 1900-02-29（原值 60）。
   显示、Copy As、自动适应列宽都使用原生日期文本；数值摘要继续使用序号。
3. 选 `A20:A23` → `Series…` → `Date sequence`，样本数 1，生成逐日日期。
   选 `C20:C24`，样本数 2，生成 2024-03-31、04-30、05-31，保持月末。
   两个相隔 7 天的样本按周延续，逆序样本反向延续；全部由 Rust 推断。
   填充柄自动识别带日期格式的原生数值，支持四方向；Ctrl/⌘ 保持复制语义。
   超出 9999-12-31 或低于序号 0 时拒绝整次写入；无规律样本在显式序列中报错，
   在自动拖拽中按原样循环复制。生成值及格式可一步撤销。

外部 TSV 识别日期数值，但沿用现有约定保留目标格式（常规格显示 45351）；
内部复制／粘贴保留日期格式。当前不提供时间输入、地区日期猜测、1904 切换、
完整自定义日期格式 UI、多列独立日期序列或双击填充；这些不能算本批完成。

最短链路不变：React 事件 → UI Core 既有 command atom → 一次 Rust Worker 命令 → 返回投影。
只在现有输入、格式、填充三个入口接入；没有日期 atom、日期 Worker 或计算镜像。
