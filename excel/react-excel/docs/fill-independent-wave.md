# 独立序列与双击填充

## 本批三个功能

1. 多列竖向拖拽：每列分别识别数字、编号、日期或名称序列，不能识别的列按原样复制。
2. 多行横向拖拽：每行分别识别规律，支持向左及向右；Ctrl/⌘ 仍强制全部循环复制。
3. 双击右下角填充柄：沿相邻连续数据向下填充，成功后选择完整结果，一步撤销／重做。

双击优先检查紧邻左列；左列没有贯穿源样本并向下延续的数据，再检查紧邻右列。
遇到首个空格即停止，不跨空洞、不超出当前工作表画布；0、FALSE、返回空文字的公式均算有数据。
没有连续数据明确提示，不写入、不增加历史。目标合并／数组区域等沿用既有原生拒绝规则，
失败不部分写入，修正后可重试；忙碌期间不会重复提交，也不会抢回用户已改选的选区。
不包括自定义列表管理／拖拽，也不将原计划 #12 或整个 41 项产品范围记为全部完成。

## 归属与必要性

`React 事件 → 既有拖拽 command atom → 既有 fillSelectionAtom → 一次 range.fill → Rust → 投影`

- React 仅增加双击事件和翻译后的提示；不读取数据、推断规律或维护新状态。
- UI Core 复用保护、忙碌、历史及投影发布，接收 Rust 确定的实际目标；不扫描工作簿。
- Worker 在同一请求内先查询 Rust 连续末行，再调用既有原生填充；未新增命令或桥接层。
- `auto_fill/adjacent.rs` 只查询稀疏地址末行；不求值、不生成 atom。
- `auto_fill/apply/inferred.rs` 只计划各行／列的推断结果：先整体预算，再逐条预检，
  最后统一计算共边并写入，复用一次原生历史，避免后列失败而前列已修改。

新增文件按两项原生职责拆开，没有新增 runtime 层。普通新增／大改文件低于 300 行。
存量 `auto_fill.rs`、Worker `runtime.ts`、协议 `commands.ts`、翻译映射仍超 300 行，
本次仅增加必要声明／接线，不扩大为无关重构；`wasm-types.ts` 为 300 行。
