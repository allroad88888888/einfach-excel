## 已实现的原生链路

`workbook.find / workbook.replace` → WASM 参数转换 → Rust 稀疏查询／替换事务。
查询仅返回匹配坐标、UTF-16 位置及修订版；替换返回计数、同版本投影与当前表完整稀疏尺寸。

- `find_text.rs`：字面量匹配，可区分大小写、匹配整格；大小写转换使用 Unicode 字符小写映射，
  匹配边界必须对应完整原字符，对外为非空 UTF-16 半开区间。
- `workbook_find.rs`：按表序、行序、列序扫描；覆盖离屏内容，多表／交叉范围去重。
  页大小 1–500，只限制返回列表，不限制总数。一个格内有多处命中时分别返回位置。
- 公式模式搜索公式源，数字使用完整往返精度；值模式搜索计算结果，数字使用原生有效格式。
  日期／自定义格式的完整 UI 投影一致性仍随各自功能项核对，不能声称所有格式已一致。
- `workbook_history_replace.rs`：冻结本次完整匹配计划，只保存实际改变格子的历史。
  当前替换只处理指定位置；全部替换不使用分页列表，不递归替换新生成的文字。
  原文字格保持文字，替换为空则清空；公式沿用原生输入解析与循环检查。
- 错误在同一个 Store batch 内回滚，包含前面已经写入的格子；跨表替换是一条历史，
  no-op 不生成历史、不清除 redo。值模式拒绝覆盖公式结果；spill 子格拒绝写入。
- 查询词限 4096 UTF-8 字节，替换词限 1 MiB；分配前检查单格结果 16 MiB、
  整次结果 32 MiB／100,000 个改动格。超限整次报错，绝不静默截断“全部替换”。

## 传输边界

- `wasm_workbook_find.rs` 只转换参数；未知查询选项、非法整数不会悄悄改变搜索含义。
- `find-commands.ts` 定义直接命令的数据形状；`find-io.ts` 只做稳定表 ID 与原生索引映射。
- 替换前核对 Worker 当前 revision。查找后编辑、撤销、移动表等使旧查询失效，旧结果不能再写。
  原生成功写入即推进 revision，即使随后投影失败，也不会再次接受旧查询。
- `runtime.ts` 保持 300 行以内；原有尺寸操作归入 `resize-io.ts`，尺寸读取继续留在 `size-io.ts`，
  避免“尺寸读取 → 可见投影 → 尺寸读取”的循环依赖。原生尺寸语义没有改变。
- 没有新增 backend、ticket、ledger、重试层或工作簿副本；旧 find-replace 的回调编排不作为 React 接线目标。
