# 通配符与结果列表批次

本批三项：通配符查找、查找全部列表、点击结果定位。已验收，随本次提交。

## 交互与边界

- 默认字面量模式保持不变；勾选 Use wildcards 后，`*` 匹配任意字符序列，`?` 匹配一个原 Unicode 字符，
  `~*`、`~?`、`~~` 查找对应符号。其他字符保持字面含义，不支持正则表达式。
  符号语义依据 [Microsoft 通配符说明](https://support.microsoft.com/en-us/excel/using-wildcard-characters-in-searches)。
- 项目采用最左、最长、非重叠的匹配位置，空匹配不作为替换目标；这项具体位置策略不冒充完整 Excel 一致性证明。
- Find all 展示完整查询总数，每页 100 条，支持首页、上页、下页、末页；分页只控制返回量，不截断查询或全部替换。
  列表按匹配处计数，同一个单元格内多处匹配可分别定位；Position 列使用现有 UTF-16 区间的一基显示。
- 点击结果会重新向 Rust 查询该位置，旧列表的 revision 不符就清掉列表并提示重新查找，不能把同一序号静默定位到新数据。
  跨表仍通过原有工作表激活、选区、滚动命令。翻页默认定位新页第一个匹配。
- 修改查询条件会清掉结果，修改替换文字保留结果；成功替换清掉旧结果，撤销仍由 Rust 保存。

## 最短调用链

React 事件 → `runFindReplaceAtom` → 原有 `workbook.find / workbook.replace` → Rust → 面板 atom → React。

- `find_wildcard.rs` 只负责匹配区间。已有公式条件匹配器仅返回布尔值，不能提供替换所需的完整原文边界，
  本批不改它的既有公式语义，也不让 lite WASM 引入正则依赖。
- 原字符边界与大小写展开边界分开存储，`İ` 的展开和 emoji 均不导致替换截断字符。
  动态规划保存两行终点数组，没有指数回溯；估算工作量超过 16,000,000 时整次明确报错，原生写入前完成检查。
- UI Core 在已有 result 内保存一页坐标，没有新增 atom、ticket、重试层或工作簿副本。
- `FindResults.tsx` 只负责列表 DOM。面板状态和点击处理直接使用 `useAtomValue/useSetAtom`，没有 controller props。
