## 已完成的原生链路

- `Workbook::try_structural_edit` 统一四种位移的几何及尾部溢出预检。
- 同表/跨表引用随数据移动；删除保留公式外层、IFERROR 及范围幸存部分。
- 冷公式不因随动整体变热；修复越界引用、带空白 spill 后缀的冷/热差异。
- `WorkbookHistory::edit_structure` 把一次插删记入既有 50 条 / 32 MiB 历史栈。
- 保存目标表被移动的稀疏带、带外被改写的公式、目标表尺寸/格式/可见性/筛选/Table 元数据。
- 不保存计算结果或 spill 子格；不复制无关工作表及未移动的前缀大文本。
- 恢复先检查工作簿/工作表身份和 Table 名称冲突，再还原原始存储，最后投影数组并恢复通知。
- 还原同时更新稀疏范围成员通知，避免 `SUM(A:A)` 继续返回恢复前的缓存值。
- `WasmWorkbook.edit_structure(sheet, action, at, count)` 直接调用原生历史；成功后清除旧剪贴板。
- `history_state` 增加可选 `structuralEdit: { action, at, count }`，只供宿主调整视图，不包含历史数据。
- 普通单格、工作表管理、隐藏操作的历史仍走同一栈；不新增 JS 撤销器。

按职责抽出了历史条目的回放分派，`workbook_history.rs` 249 行；普通新增文件均不超过 300 行。
存量 `tests/lazy_structural_retarget.rs` 410 行，只修改一条过期的“删除引用即丢弃公式”断言。

## 本轮接入的产品链路

`StructureTools` → `runSelectionStructureAtom` → 一次 `sheet.editStructure` → Rust → 返回投影。
菜单只读 atom、发 command；没有 React 业务状态或 JS 单元格位移器。

- 插入位置为当前连续选区的起点，数量为该选区占用的行数或列数。
- 演示画布插入后增长、删除后缩小，至少保留一行一列；超过 Excel 行列上限会拒绝。
- Worker 一次返回新画布数量、可见格、完整稀疏尺寸、隐藏集合及原生历史目录。
- UI Core 校验返回身份及几何后发布；选中坐标保留，超出新边界才收紧，不重置到 A1。
- 历史条目的 `structuralEdit` 只计算画布数量；原始值、公式、样式的恢复仍由 Rust 完成。
- 尺寸刷新覆盖新旧画布，清除已删尾部的缓存，屏幕外行高/列宽也正确移动。
- 编辑、剪贴板、隐藏、尺寸、工作表及历史忙碌时拒绝插删；保护检查涵盖可能被改写引用的工作表。
- 插删未确认时阻止新的编辑入口、格式/清除、剪贴板、隐藏、尺寸、工作表及历史写入。
- 插删及结构历史使旧原生剪贴板 token 失效，重新复制后才可粘贴。

复用 A2/C2 的字体样例、G2 公式、Summary 的跨表公式、40px 行高、200px 列宽及隐藏种子；
没有新增 demo 数据副本。新增源码分别负责菜单、插删命令、可见忙碌反馈，普通文件均 ≤300 行。
