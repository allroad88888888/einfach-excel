# 排序批次

本批只做三个入口：升序、降序、多列排序。排序数据只由 Rust 改动。

## 手工验收

演示地址：`http://127.0.0.1:5183`，切到 Summary。
原生种子 `A25:C29` 包含 Team、Score、Record 三列表头及四条乱序记录，
其中 W20 是粗体、E10 是斜体、E30 有下划线。

1. 选 `A26:C29` → Sort → Sort ascending。
   Record 应依次是 E10、E30、W20、W10，同行三列一起移动。
2. 选 `B26:C29` → Sort descending。
   Record 为 E30、W20、E10、W10；相等项保持原先顺序。
3. 选 `A25:C29` → Custom sort，勾选 First row is a header，
   第一层 A 升序，Add level 添加 B 降序，Apply sort。
   表头不动，Record 为 E30、E10、W20、W10。

每项从原始数据开始，或先撤销上一项。已排序时提示 Already in order，
不添加历史步骤。有效排序、样式随动、跨表依赖可以一步撤销/重做。

## 本批边界

- 只排序明确选中的一个矩形，不自动扩大到邻接数据。快捷入口按最左列排序，
  不猜表头；单格、非连续多区拒绝。整条记录移动必须选中全部相关列。
- 多列面板按层级顺序比较，最多 8 个不同列；文本比较不区分大小写。
- 包含隐藏行，行高、行样式、隐藏位置固定在原行，列属性不移动。
  单元格显式样式随原生格子移动；不改变三类 style 的既有规则。
- 空值始终沉底；公式按计算结果排序。沿用现有 Rust 契约：移动公式保留源码，
  不重写相对引用，不把公式转换为结果常量。
- 合并格、活动 spill 由 Rust 拒绝；保护工作表由 UI Core 写入门禁拒绝。
  完整原生保护仍属原计划未完成项，不能以此宣称已完成。
- 单次至多 1,048,576 格，历史快照保留在 Rust。排序后旧剪切 token 失效，
  避免后来粘贴清掉另一条记录；普通复制快照保留。
- 取消/Escape 不写入，原生拒绝保留面板选项供修正。

不包含筛选、按颜色/自定义顺序排序、自动扩展选区，不把整个 27–30 项记为完成。

## 最短实现链

`SortTools → sortSelectionAtom → range.sort → sortRange → Rust sort_range → visible projection`

- React：选择控件、模态焦点、反馈，全部用 `useAtomValue/useSetAtom`。
- UI Core：一个排序 command 读取选区；面板 atom 只保存用户选项。
- Worker：`sort-io.ts` 校验参数并归入原生历史，不读取样本或建立行映射。
- Rust：复用稳定排序及 Store 传播；仅补合并格拒绝，不复制算法。
- 结果：同一个回复带回可见投影，不追加刷新请求或本地撤销快照。

跨表撤销同时修复等待态：history 请求未完成时发布 busy，标签据同一个 atom
禁用，避免按钮仍可点击而命令静默拒绝。
